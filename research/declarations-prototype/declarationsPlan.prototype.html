Declarations and the three-way plan: one Table, by hand

PROTOTYPE, throwaway. sheets-framework #183, part of the map #178.

The question

An agent edits a sparse declarations file saying what the spreadsheet will be, only for the properties it names. gen:configs compares three things for each declared property: the declarations, the last generated configs (what the sheet looked like last time) and the live sheet. Unchanged declarations with a changed sheet: a person's change, so stop. Changed declarations with an unchanged sheet: an agent's change, so apply. Anything the declarations leave out belongs to the sheet.

Does that rule hold up on the occPayment Table? Watch two traps from the research: a column type change resends the Table's whole column list (every dropdown on the Table rides along), and the last generated configs record what the sheet looked like, not what was last applied, so a regen at the wrong moment can make a person's edit look like an agent's.

Column IDs, headers and the ID prefix opy are real (from real-estate/src/generated/). Column types, formula text, typed-cell counts and dropdown styles are illustrative. Nothing here talks to Sheets. Deletion isn't modelled: #184 decides its marker.
