# Sheets behaviour

An [observation index](https://github.com/byronbroughten/byro-repo/blob/master/docs/agents/prose-files.md#terms) of how Google's platforms behave (the Sheets UI, the Sheets REST API, Apps Script with `SpreadsheetApp` and triggers, and the Google auth they share), measured costs included, never the framework's own behaviour. It is grouped by subject and follows the [observation-index rules](https://github.com/byronbroughten/byro-repo/blob/master/docs/prose-style.md#observation-indexes).

Whoever settles or overturns an observation adds or updates its line in the same change as the finding.

Write-ups sourced from Google's docs live on `research/*` branches, listed by `git branch -r --list 'origin/research/*'`.

## Tables and growth

### Appending rows to a Table

- Observed: REST API v4 `appendCells` with a `tableId` grew the grid by the rows it inserted, and `appendCells` with no `tableId` wrote after the last row holding a value; scratch tab on the dev spreadsheet; 2026-09-26; [recorded in db5ba74](https://github.com/byronbroughten/sheets-framework/commit/db5ba74d35cb24b9cf97975a1d86a589b88c7a76).
- Observed: REST API v4 `appendCells` keyed on a `tableId` inserted whole sheet rows below the Table's last row: a stray value below, a lower Table with its head rows, and a value in a column outside the Table all moved down by the appended count, and an empty row between the Table and the next occupied row stayed a gap; side by side with headers on one row, a shorter neighbour Table was untouched, a same-height one grew by a blank row, and a taller one got a blank row inside its body; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #56](https://github.com/byronbroughten/sheets-framework/issues/56).
- Observed: REST API v4 `appendCells` onto a Table whose only body row was blank wrote into that row, and nothing below moved; scratch tab on the dev spreadsheet; 2026-10-02; [resolution on #56](https://github.com/byronbroughten/sheets-framework/issues/56).
- Observed: REST API v4 `appendCells` onto a header-only Table returned `Internal error encountered.`, for a Table shrunk to its header and for one created header only; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #56](https://github.com/byronbroughten/sheets-framework/issues/56).
- Observed: On the row REST API v4 `appendCells` added to a Table, Google filled the formula columns (an A1 formula and a `SINGLE` Table reference), and the row kept the column types, the alternating colours, the body cells' text formatting and background and an untyped column's cell-level checkbox validation; a conditional-format rule ending at the Table's last row grew from `A4:A6` to `A4:A8`; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #59](https://github.com/byronbroughten/sheets-framework/issues/59), [resolution on #61](https://github.com/byronbroughten/sheets-framework/issues/61).

### Growing a Table with an insert and a widen

- Observed: A REST API v4 `insertRange` (`ROWS`) directly below a Table's last row, bounded to its columns, left the Table's range alone, and an `updateTable` widening the range by the new rows, in the same batch or a later one, took them in; on a header-only Table and on Tables with body rows; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #56](https://github.com/byronbroughten/sheets-framework/issues/56), [resolution on #59](https://github.com/byronbroughten/sheets-framework/issues/59).
- Observed: In REST API v4 growth by `insertRange` below the Table plus an `updateTable` widen, a stray value directly below in the Table's columns and a lower Table within its columns (with head rows, touching it, or narrower) moved down by the inserted count intact, a value in a column outside the Table stayed put, and a side-by-side neighbour of the same height or taller was untouched; two growths of one Table in one batch each saw the earlier one; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #59](https://github.com/byronbroughten/sheets-framework/issues/59).
- Observed: The same REST API v4 growth with a lower Table wider than the growing one was refused with `Invalid requests[0].insertRange: You cannot insert or delete cells over part of a table.`, and the batch changed nothing; scratch tab on the dev spreadsheet; 2026-10-02; [resolution on #59](https://github.com/byronbroughten/sheets-framework/issues/59).
- Observed: The rows REST API v4 growth by `insertRange` plus an `updateTable` widen added kept the column types (`CURRENCY` and `NUMBER` formats, both `DROPDOWN`s, `BOOLEAN`), the alternating colours and a whole-column conditional-format rule, and had empty formula cells, none of the body cells' text formatting or background, and no cell-level checkbox validation; a conditional-format rule ending at the Table's last row stayed `A4:A6`; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #59](https://github.com/byronbroughten/sheets-framework/issues/59), [resolution on #61](https://github.com/byronbroughten/sheets-framework/issues/61).

### Inserting and deleting cells beside and inside a Table

- Observed: A REST API v4 `insertRange` or `deleteRange` (`ROWS`) bounded to one Table's columns grew or shrank only that Table, leaving a side-by-side Table's range and values untouched; a `deleteDimension` of a sheet row, and a `deleteRange` across both Tables' columns, shrank both Tables; probe sheet on the dev spreadsheet; 2026-10-01; [resolution on #53](https://github.com/byronbroughten/sheets-framework/issues/53).
- Observed: A REST API v4 `insertRange` or `deleteRange` shifted only the cells inside the range's band, a Table the band held whole moved with it, a Table grew by an insert strictly inside it and not by one just below its last row or just past its last column, and an insert strictly inside a Table gave its new cells the format and validation of the cells below; scratch tabs on the dev spreadsheet; 2026-10-02, rerun 2026-10-03; [recorded in 7ff741d](https://github.com/byronbroughten/sheets-framework/commit/7ff741d434fda5aa91d3763c5e5da711c75ddf27).
- Observed: A REST API v4 `deleteRange` (`ROWS`) bounded to a Table's columns removed its only body row, and both of two body rows, leaving the Table header only; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #56](https://github.com/byronbroughten/sheets-framework/issues/56).
- Observed: A REST API v4 `deleteRange` of a Table's header row was refused with `Cannot delete a table header row. Consider hiding the row instead.`; dev spreadsheet; 2026-10-01, rerun 2026-10-03; [resolution on #53](https://github.com/byronbroughten/sheets-framework/issues/53), [recorded in 7ff741d](https://github.com/byronbroughten/sheets-framework/commit/7ff741d434fda5aa91d3763c5e5da711c75ddf27).
- Observed: A REST API v4 `insertRange` or `deleteRange` whose band cut part of a Table was refused with `Invalid requests[<i>].<kind>: You cannot insert or delete cells over part of a table.`, naming only the request; scratch tabs on the dev spreadsheet; 2026-10-03; [recorded in 7ff741d](https://github.com/byronbroughten/sheets-framework/commit/7ff741d434fda5aa91d3763c5e5da711c75ddf27).
- Observed: REST API v4 sheet row and column inserts and deletes shifted the Tables, their column types, conditional-format ranges and hidden indexes with the rows and columns; a column insert at a Table's end grew it only with `inheritFromBefore: true`, which headed a new column `Column <n>`, and a delete inside a Table shrank it; scratch tab on the dev spreadsheet; 2026-09-26; [recorded in db5ba74](https://github.com/byronbroughten/sheets-framework/commit/db5ba74d35cb24b9cf97975a1d86a589b88c7a76).
- Observed: A REST API v4 column insert with `inheritFromBefore: true` at a Table's end copied its left neighbour's cell format and cell validation into every row, above the Table too, a copied checkbox arriving unticked (`false`), and copied no Table column type or column validation rule, beside a checkbox, dropdown and currency column; scratch tab on the dev spreadsheet; 2026-09-26; [recorded in 98a56b4](https://github.com/byronbroughten/sheets-framework/commit/98a56b489b733aa931c1de779e497c1bfc972266).

### Column inserts bounded to a Table

- Observed: A REST API v4 `insertRange` (`COLUMNS`, rows from three above the header to the Table's last row) at a Table's last column widened the Table with the new column second to last, headed `Column 1`; just past the last column it left the Table's range alone and shifted the band's cells to the right; just past the last column with an `updateTable` widening the range in the same batch, the Table widened with the new column last, headed `Column 1`; cells above and below the band stayed put; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #56](https://github.com/byronbroughten/sheets-framework/issues/56).
- Observed: With a side-by-side neighbour Table on the same header row, that REST API v4 column insert moved a neighbour of the same height or shorter right whole, head rows included, and was refused with `Invalid requests[0].insertRange: You cannot insert or delete cells over part of a table.` for a taller neighbour, with or without its head rows, and for a neighbour whose Table range started above the band; scratch tabs on the dev spreadsheet; 2026-10-02; [resolution on #56](https://github.com/byronbroughten/sheets-framework/issues/56).
- Observed: In the Sheets UI, a column insert inside the left of two side-by-side Tables with headers on one row went through when the right Table was the same height or shorter, and was blocked when it was taller; sheet not recorded; 2026-10-02; [operator's comment on #56](https://github.com/byronbroughten/sheets-framework/issues/56).
- Observed: A REST API v4 column insert at a Table's end with no `inheritFromBefore` left its new cells with no number format, background, borders or validation, beside a `NUMBER`-formatted column; the Layout tab's grid read 5 columns before and 6 after, the insert starting inside the grid; Layout tab on the dev spreadsheet, read with `exerciseLayout` dry runs either side of its send and a probe of the cells; 2026-10-09; [closing comment on #141](https://github.com/byronbroughten/sheets-framework/issues/141), [recorded in 919aa4d](https://github.com/byronbroughten/sheets-framework/commit/919aa4da76040d632e65988e2de7ccd6fb4251cd).

### The grid's edge

- Observed: A REST API v4 `appendDimension` added rows or columns past the grid's edge and moved nothing; scratch tabs on the dev spreadsheet, whether a Table sat at the edge not recorded; 2026-10-03; [recorded in 7ff741d](https://github.com/byronbroughten/sheets-framework/commit/7ff741d434fda5aa91d3763c5e5da711c75ddf27).
- Observed: A REST API v4 `insertRange`, `deleteRange` or `copyPaste` whose range started past the grid's edge was refused with `Range ('<tab>'!A8:C9) exceeds grid limits. Max rows: 7, max columns: 10`, and one that ran past it was clipped to the grid; a `deleteRange` left the grid's size as it was; scratch tabs on the dev spreadsheet, whether a Table held the range not recorded; 2026-10-03; [recorded in 7ff741d](https://github.com/byronbroughten/sheets-framework/commit/7ff741d434fda5aa91d3763c5e5da711c75ddf27).
- Observed: A REST API v4 `insertRange` grew the grid only as far as the non-empty cells it pushed past the end: on a 10-row grid with values on rows 7–9, 2 rows inserted at row 5 grew it to 12; on a 514-row grid with content ending at row 503, 100 rows inserted at row 504 left it at 514, and an `updateCells` in the same batch failed with `Attempting to write row: 514, beyond the last requested row of: 513`, rejecting the batch; scratch tabs on the dev spreadsheet; 2026-10-02; [addendum on #59](https://github.com/byronbroughten/sheets-framework/issues/59).

### Copying format and validation onto new rows

- Observed: A REST API v4 `copyPaste` from a Table's last body row onto rows growth added: `PASTE_FORMAT` restored the cell formatting (number format, background, text style) and grew a conditional-format rule ending at the last row from `A4:A6` to `A4:A8`, and carried no cell-level validation; `PASTE_DATA_VALIDATION` restored an untyped column's cell-level checkbox; one source row tiled over several new rows; neither touched the values or the formula fill, placed before or after them in the batch; a lone blank body row served as the source the same way; scratch tabs on the dev spreadsheet; 2026-10-02, rerun 2026-10-03; [resolution on #61](https://github.com/byronbroughten/sheets-framework/issues/61), [recorded in 7ff741d](https://github.com/byronbroughten/sheets-framework/commit/7ff741d434fda5aa91d3763c5e5da711c75ddf27).
- Observed: REST API v4 cell-level `setDataValidation` on a typed Table column, `TEXT` included, was refused with `This operation is not allowed on cells in typed columns.`; scratch tab on the dev spreadsheet; 2026-10-02; [resolution on #61](https://github.com/byronbroughten/sheets-framework/issues/61).

### Creating and updating Tables

- Observed: REST API v4 `addTable` wrote its own `columnProperties` names three columns right of the Table, and, on a Table whose grid ended short of those columns, replied with a 500, `Internal error encountered`; dev spreadsheet; 2026-09-23, seen again 2026-10-01; [recorded in aaa7f6a1](https://github.com/byronbroughten/byro-repo/commit/aaa7f6a12d203fe320f84c8392021a3723fcd20a), [resolution on #53](https://github.com/byronbroughten/sheets-framework/issues/53).
- Observed: REST API v4 `addTable` with no `tableId` got a numeric ID in the reply, and `addTable` with `tableId: "tbl-7f3a9c21e4"` followed by an `updateTable` on that ID in the same batch set the column names, the ID reading back unchanged; scratch tab on the dev spreadsheet; 2026-10-02; [resolution on #59](https://github.com/byronbroughten/sheets-framework/issues/59).
- Observed: A REST API v4 `updateTable` field mask replaced only its fields (`name`, `range`, `columnProperties`); a `columnProperties` list replaced the Table's whole list, a column left out keeping its header cell and losing its type and validation, a sent `columnName` written to the header cell, and a sent column with no name rejected; scratch tab on the dev spreadsheet; 2026-09-26; [recorded in db5ba74](https://github.com/byronbroughten/sheets-framework/commit/db5ba74d35cb24b9cf97975a1d86a589b88c7a76).

### Sorting

- Observed: A REST API v4 `sortRange` ascending put numbers, then text, then booleans (`FALSE` before `TRUE`), descending put them in the exact reverse, and blanks sorted last in both; scratch tab on the dev spreadsheet, whether a Table held the range not recorded; 2026-09-26; [recorded in db5ba74](https://github.com/byronbroughten/sheets-framework/commit/db5ba74d35cb24b9cf97975a1d86a589b88c7a76).

## Protections

### Lock editors

- Observed: A lock added through REST API v4 naming no editors read back with the spreadsheet's editors (two gmail users and a service account), and in the Sheets UI the owner edited its cells (Num) with no prompt and no block; Table data column on `test`; 2026-09-17; [recorded in a03c0a6a](https://github.com/byronbroughten/byro-repo/commit/a03c0a6af3e6ba86a5eafcbc229d4a90333d06af).
- Observed: A lock added through REST API v4 naming users read back with exactly those users, none of the spreadsheet's other editors added; `test`; 2026-09-17; [recorded in a03c0a6a](https://github.com/byronbroughten/byro-repo/commit/a03c0a6af3e6ba86a5eafcbc229d4a90333d06af).
- Observed: With a lock added through REST API v4 naming one gmail address on Column currency's bounded data range, the Sheets UI blocked the spreadsheet owner's edits to those cells, and an edit to the last row, which sat outside the range, went through; the address sent and the address read back were not kept; `test`; 2026-09-17; [recorded in a03c0a6a, corrected in 28fbbd79](https://github.com/byronbroughten/byro-repo/commit/28fbbd792bea56805b6edc54646280ef60fe50de).
- Observed: The Sheets UI refused to create a lock that would lock the acting user out, and REST API v4 accepted such a lock; the sheet was not recorded; 2026-09-17; [recorded in 28fbbd79](https://github.com/byronbroughten/byro-repo/commit/28fbbd792bea56805b6edc54646280ef60fe50de).

### Reading protections back

- Observed: A REST API v4 `getByDataFilter` returned the same `protectedRanges` payload as a plain get with a `protectedRanges` fields mask; `test`; 2026-09-17; [recorded in a03c0a6a](https://github.com/byronbroughten/byro-repo/commit/a03c0a6af3e6ba86a5eafcbc229d4a90333d06af).
- Observed: An open-ended warning added through REST API v4 (start row and column bounds, no `endRowIndex`) read back with no `endRowIndex`, as `G5:G`; Table data column on `test`; 2026-09-17; [recorded in a03c0a6a](https://github.com/byronbroughten/byro-repo/commit/a03c0a6af3e6ba86a5eafcbc229d4a90333d06af).
- Observed: A warning added through REST API v4 with no editors read back with an `editors` list; `test`; 2026-09-17; [recorded in a31f1523](https://github.com/byronbroughten/byro-repo/commit/a31f1523b33625f3fe9ca136ac995703f232aa71).
- Observed: After the probe's four protections were deleted, a REST API v4 get with a `protectedRanges` fields mask returned `test` with no `protectedRanges` field; 2026-09-17; [recorded in a03c0a6a](https://github.com/byronbroughten/byro-repo/commit/a03c0a6af3e6ba86a5eafcbc229d4a90333d06af).
- Documented: REST API v4's `ProtectedRange.range` reference says a fully unbounded range is considered a protected sheet, and its `GridRange` reference says a missing index leaves the range unbounded on that side; read 2026-10-31; [quoted on #195](https://github.com/byronbroughten/sheets-framework/issues/195#issuecomment-6553553665).
- Documented: REST API v4's `ProtectedRange` reference says that on a write with `warningOnly` true the `editors` are ignored, and that editors are not supported with `warningOnly` protection; read 2026-10-31; [quoted on #195](https://github.com/byronbroughten/sheets-framework/issues/195#issuecomment-6553553665).

### Rows added below a protection

- Observed: An open-ended warning added through REST API v4 (no `endRowIndex`) reaching below the data prompted in the Sheets UI on a cell under the Table, and on a cell in a Table row added afterwards; Table on `test`; 2026-09-17; [recorded in 28fbbd79](https://github.com/byronbroughten/byro-repo/commit/28fbbd792bea56805b6edc54646280ef60fe50de).
- Observed: A protection with a concrete end row kept that end row when 1000 rows were added to the sheet; `test`; 2026-09-17; [recorded in 28fbbd79](https://github.com/byronbroughten/byro-repo/commit/28fbbd792bea56805b6edc54646280ef60fe50de).
- Observed: `$E5:E` typed into the Sheets UI's protected-range editor was saved with a concrete end row, the sheet's last row at the time; `test`; 2026-09-17; [recorded in 28fbbd79](https://github.com/byronbroughten/byro-repo/commit/28fbbd792bea56805b6edc54646280ef60fe50de).

### Warning prompts

- Observed: A warning's `description` showed in the Sheets UI's Protected sheets and ranges sidebar and not in its prompt, which carried no custom message; `test`; 2026-09-17; [recorded in 28fbbd79](https://github.com/byronbroughten/byro-repo/commit/28fbbd792bea56805b6edc54646280ef60fe50de).
- Observed: With the probe's warnings and locks on its data columns, the Sheets UI refused a column drag for every column; `test`; 2026-09-17; [recorded in a03c0a6a](https://github.com/byronbroughten/byro-repo/commit/a03c0a6af3e6ba86a5eafcbc229d4a90333d06af).
