# Structure is declared in code; identity is recorded from the sheet

Design reasoning. The one-line principle lives in [`docs/design.md`](../design.md); this file holds its instances.

## Instances

[ADR 0017](../adr/0017-declare-the-config-sheet-floors-structure-in-a-seed-and-take-its-identity-from-the-generated-configs.md) splits the config-sheet floor along this line, and rejects seeding fixed GIDs because the framework serves other spreadsheets than this one. An ID prefix is identity, so it is read from the sheet's column IDs rather than declared in code or in the generated-config cache; using the cache as an input to its own regeneration would lose prefixes on a reset and let two branches assign the same one ([ADR 0012](../adr/0012-assign-each-sheets-id-prefix-once-and-sample-it-from-its-column-ids.md) samples the prefix from the column ID row and rejects the cache as its source). Every Table's head and its ID shape are structure, so they are declared in one code constant, `tableLayout` ([ADR 0026](../adr/0026-declare-the-table-layout-and-id-shape-in-one-framework-constant-not-on-spreadsheet-config.md) moves the delimiter, the ID and Name headers and the layout indexes off Spreadsheet Config's cells; [ADR 0027](../adr/0027-give-each-table-its-own-head-rows-at-fixed-offsets-above-its-header.md) declares which head rows sit above a header, and at what offsets). A `tableId` is identity even when the framework mints it ([ADR 0028](../adr/0028-identify-a-table-by-its-live-tableid-and-mint-a-random-one-for-a-table-the-framework-creates.md) gives a created Table a random `tableId` unrelated to its name, read from the sheet like any other from then on).
