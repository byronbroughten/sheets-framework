# Record a deliberate absence as deliberate

Design reasoning. The one-line principle lives in [`docs/design.md`](../design.md); this file holds its instances.

## Instances

- The endpoint entry's selector is an anonymous nested object rather than a named `EndpointSelector<TN>`, and the run takes a structural copy of the entry rather than `Endpoint<TN>` — two references to one named generic type are compared by its measured variance, which the column filter leaves unmeasurable, so naming either shape breaks the dispatch boundary's widening in a file the editor never opened (#11; `docs/architecture/endpoint-dispatch.md`).
- There is no type-level bridge from relative `<TN, CN>` addressing to an absolute `ColumnFullName`, because building one enumerates the whole Table-by-column cross product before it can prune ([ADR 0015](../adr/0015-leave-relative-and-absolute-column-addressing-unbridged-at-the-type-level.md) records the prototype that ruled it out; `docs/architecture/column-addressing.md`).
- There is no base class for the concrete column alone: a class beside `ColumnNamed` extends `ColumnBaseNamed` and reaches the column through a getter rather than inheriting the concrete class's members, because it exists to offer a narrower set of methods than that class's whole surface (`docs/architecture/class-chains.md`; `docs/code-style/class-shape.md`).
- The Raw tier's `TableCommonRaw` sits between the tier base class and the concrete Table classes (`TableRaw`, `TableColumnResolverRaw`) rather than being folded into it, because the row and column base classes hang off that base and two of its members would be illegal overrides there ([ADR 0016](../adr/0016-hold-the-raw-tiers-shared-table-members-between-its-base-class-and-its-concrete-classes.md) records the class as decided, so it isn't folded back as a simplification; #6; `docs/architecture/class-chains.md`).
- The config-sheet floor's generated entries are never hand-edited: the seed declares the floor's structure and the generated files hold its identity, so a missing floor part is created from the seed and a drifted one overwritten, rather than anyone "fixing" an entry by hand ([ADR 0017](../adr/0017-declare-the-config-sheet-floors-structure-in-a-seed-and-take-its-identity-from-the-generated-configs.md) makes the repair the sync's job; `docs/generated-data/config-sheet-floor.md`; the rule: `src/01_SpreadsheetSchema/AGENTS.md`).
- `IF` does not default to `false` on `ColumnFullName`, because that would silently shrink the union endpoint dispatch is keyed on.
- The Node host reaches Sheets and nothing else — no triggers, no Gmail, no Docs — and `ScriptApp`/`SpreadsheetApp` are left uninstalled so a chore reaching for one fails by name instead of half-working; the boundary is recorded as a boundary precisely so nobody reads the missing globals as an unfinished adapter ([ADR 0018](../adr/0018-give-the-framework-a-node-host-that-reaches-sheets-and-nothing-else.md) draws the boundary when it gives the framework its second host; #25).
- Chores carry no tests, because a test for a one-off would restate the chore, and its real check is the dry-run preview read before saying send (#25; `docs/architecture/chores.md`).
- Edit-protection writes do not expose `domainUsersCanEdit`, `UpdateProtectedRange`, or Table- and named-range-backed protections: a drifted protection is replaced, not edited; a Table-backed one can't be limited to one column (#50; `docs/architecture/edit-protections.md`).
- The config-sheet floor carries no edit locks: a lock naming no editors inherits the spreadsheet's editors and stops nobody, and the only lock that keeps another editor out names editors explicitly, which needs an address list this repo has nowhere to keep — so the floor is warnings-only, and keeping another editor out is out of scope rather than half-built ([ADR 0002](../adr/0002-protect-the-config-sheet-floor-with-edit-warnings-not-edit-locks.md) records the floor as warnings-only because a lock that keeps an editor out needs an address list with nowhere to live; `docs/architecture/edit-protections.md`). Drift repair covers a protection's range and content but not its editors, so an editor added by hand goes unnoticed.
- Value Config is not part of the floor. #99 had put it there, reversing #49, but once any column on a Let api access Table can be a value source, a framework-owned lists Table is just one app's choice, so the floor seeds no Table of lists and no seeded values ([ADR 0014](../adr/0014-type-a-dropdown-from-any-let-api-access-table-column-and-take-value-config-off-the-floor.md) takes Value Config off the floor once any Table column can be a value source).
- There is no Table row insert and no sheet-row delete: a Table grows only by `appendTableRows` and shrinks only by a Table-bounded `deleteRange`, so there is one way to grow and one way to shrink, and neither can cut a neighbour ([ADR 0019](../adr/0019-keep-every-row-delete-inside-its-table-and-give-a-table-no-row-insert.md) bounds every row delete to its Table and leaves the Table no row insert; `docs/architecture/table-growth.md`, `docs/architecture/row-deletes-and-sorts.md`).
- There is no `formula` tagged template: it would add two nouns (`Formula`, `Single`) for nothing but a neater call site, so formula text stays a plain string (sheets-framework#49).
- The Sheet container has no Identified class: every sheet-scoped member (title, grid size, conditional formats, edit protections, the whole-sheet lock) would only pass through to Raw, and a GID needs no resolving, so Identified adds only the Table ([ADR 0023](../adr/0023-carry-the-table-through-raw-and-identified-by-its-live-tableid-and-key-its-state-and-queues-by-table.md) leaves the sheet container without an Identified class for that reason).
- There is no up-front check of the whole layout. The framework leaves to Google every arrangement Google refuses, such as a growth that would split a wider Table below, and rewords that refusal to name the Tables. It checks only what Google can't see: head rows. A column insert refuses a neighbour it would split from its head rows, and a config sync refuses a managed Table whose head rows sit on another Table. No other check of the whole layout runs ([ADR 0021](../adr/0021-leave-to-google-every-table-arrangement-it-refuses-and-check-only-head-rows.md) leaves the refusals to Google once insert plus widen made every damaging arrangement refused).
- There is no per-read blank flag such as `value(name, "emptyAllowed")`: the column's Empty value allowed tick stays the declaration and `valueOrEmpty`/`valueNotEmpty` and their multi-column forms the override, because a flag would save only the `gen:configs` run when a tick changes, and would lose the list of reads `tsc` produces when a tick flips, the whole-row check of blank required columns, and the write-side check that lets a blank through only on a ticked column ([ADR 0020](../adr/0020-keep-the-empty-value-allowed-tick-as-the-columns-declaration-with-no-per-read-blank-flag.md) weighs the saved regen against those three).

## Corollaries

The same applies to commented-out code, which is why the general style doc's delete-dead-scaffolding rule (`@byronbroughten/config`'s `docs/code-style.md`) carves out an exception for it. Absence of an explanation is not evidence of absence of a reason — ask.
