# Profile, sampled facts, Working and head rows

The elaboration behind [docs/vocabulary.md](../vocabulary.md), whose one-line entries are the rules. These are the **architecture** words; the operator-facing ones live in [GLOSSARY.md](../../GLOSSARY.md).

If you're renaming or relocating something and aren't sure which word fits, ask rather than guess: these distinctions were deliberately hashed out, and folder placement depends on them.

- **Profile** — a Table's or column's descriptive facts as the working state holds them: a column's type, its validation, its head-row contents and its sampled facts, and a Table's column IDs and ID prefix. Config regeneration derives the configs from them. It is Raw-only: `table.profile` is a `TableProfileRaw` and `column.profile` a `ColumnProfileRaw`, and each extends its tier base (`TableBaseRaw`, `ColumnBaseRaw`) rather than the common class, since it only reads and owns no queued writes. Identified and Named reach a profile through `raw`.
  - **Which class does a member belong to?** A member goes on the profile only if it reads a descriptive fact that config regeneration derives configs from. Identity and geometry (`tableId`, name, bounds, `dataRowCount`) and everything you do to a Table or column, writing a head cell included, are on the Table or column itself.
  - **History.** The profile replaced the Meta / primary axis, under which every tier's sheets and columns came in a primary view and a `Meta` view crossed by one word (sheets-framework#63). Meta was retired in sheets-framework#85: there is no Meta class, no `meta` or `primary` crossing, and no `ss.sheetMeta`.
- **Sampled facts** — the column-wide facts read from a column's top data row: whether it holds a formula and which one, its number format type, its data-validation condition type, and its top value. They live in `ColumnStateRaw.sampledFacts` and are read through `column.profile`. They are working in the sense below: present in the working view, indexes at pre-flush positions. `TableRaw` fills them twice, and neither overwrites the other: its integration walk records them for the Table columns the payload described, because whether a cell holds a formula and what its number format is exist only while the payload is in hand, and its finalize pass then *ensures* them, blank, for the fetched Table columns it did not (#17). Only Table columns ever get them, since every consumer reaches one through a column ID and column IDs live only inside the Table. They were "active facts" until sheets-framework#114.
- **Working** — present in the working view, by fetch or queued write, with row indexes still at their pre-flush positions (`workingRows`, `cell.inWorking`). Not "exists on the sheet". On the `triggerOnEdit` path only the column ID row is ever fetched, so no data row is working — `rowIndexesFull`, derived from the Table bounds, is what names every data row. "Active" in this sense was retired in sheets-framework#114.
- **Head row** — a row of the Table's head: the header row, or one fixed above it at the offset `tableLayout.headRowOffsets` gives its role. A head row is reached by role: `table.headRow(role)`, `column.headCell(role)`, and `table.headRowByIndex` for a Table-relative head-row index already in hand, which takes the first role at that index. Two roles may share a row: `action` and `groupHeading2` are both offset 1, since a level-2 group heading sits in the action row's cells that hold no checkbox. A head row is not a profile form; reading its contents for regeneration goes through the profile, and writing them goes through the Table or column.
