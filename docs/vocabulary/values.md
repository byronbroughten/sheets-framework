# Schema and cell values

The elaboration behind [docs/vocabulary.md](../vocabulary.md), whose one-line entries are the rules. These are the **architecture** words; the operator-facing ones live in [CONTEXT.md](../../CONTEXT.md).

If you're renaming or relocating something and aren't sure which word fits, ask rather than guess: these distinctions were deliberately hashed out, and folder placement depends on them.

## Schema, and the tri-state cell

**Schema** — type/validation logic layered on top of Config data. The Schema tier (`01_SpreadsheetSchema`) is everything that reads the generated configs, and it sits below Raw because Raw reads the layout and sheet list from it. Two unrelated families share the word: the spreadsheet schema (`SpreadsheetBaseSchema`/`SpreadsheetSchema`/`SheetSchema`/`ColumnSchema`, see [schema classes](../architecture/schema-classes.md)) and the value schema (`ValueSchema`, for validating a single cell's value). **Nearly every cell is tri-state: `Value<VN>` includes `""`** — a `boolean` column reads `boolean | ""`, a `number` column `number | ""` — because an untouched cell is empty, not defaulted. The one exception is `checkbox`, whose value type is exactly `boolean` (#12); don't restore the blank to it. Code that branches on a column's value has to say what empty means rather than assuming the base type.

## `valueNotEmpty`, `valueOrEmpty` and `value`

**Three words, and the column decides what the unmarked one means.** `valueNotEmpty` excludes `""` from the return type and throws when the cell is blank, always, on every column; `valueOrEmpty` is the same read with `""` still in the union, for a caller that has decided what blank means; `value` is whichever of the two the column's own **Empty value allowed** box declares (#13) — blank-excluding when the box is unticked, blank-tolerant when it is ticked. The plurals follow the same rule — `valueArrNotEmpty` throws, `valueArrOrEmpty` doesn't, `valueArrFilterEmpty` drops the blanks, and `valueArr` is what the column declared. Only Named can see a declaration, so only Named offers `value`/`valueArr`: Identified resolves columns by generated id and exposes `valueNotEmpty`/`valueArrNotEmpty` plus the blank-tolerant pair, and Raw declines both marked-strict and unmarked words because validation isn't its job — `CellRaw`/`ColumnRaw`/`RowRaw`/`UniformRowRaw` expose `valueOrEmpty`/`valueArrOrEmpty` and nothing shorter. After that split each word means one thing at every tier it exists on. The suffix marks the *empty* axis only — every form still throws on an inactive cell, which is the separate condition of a cell absent from the working view, whether or not it exists on the sheet. `CellNamed` runs its own blank check rather than delegating to Identified's, so the message names the sheet and column the caller actually wrote instead of a generated column id (#8). **`RowNamed.blankRequiredColumnNames` asks the same declaration a different question** — which of the columns the row actually holds are blank and don't allow it — so an endpoint reporting on missing values reads the sheet's own record of mandatoriness rather than keeping a list of its own (#23). A column whose blank reads as a real value is never among them: a checkbox's blank is `false`, which is an answer, not a hole.

## The `checkbox` value name

**The checkbox was the trap, and declaring the column type is what disarms it.** A column whose type menu says Checkbox gets the `checkbox` value name, whose value type is exactly `boolean` and whose blank reads as `false`, so `column.value(rowIndex) === true` over a selector column is a plain comparison. The coercion is a `blankReadsAs` field on the value schema, applied by `CellIdentified.valueOrEmpty` — the lowest tier that knows a cell's value name — so Identified and Named agree and Raw still reports the wire. A column left on Automatic that merely *holds* `TRUE` keeps the `boolean` value name, keeps its blank, and keeps counting toward the untyped tally; the trap is still live there, and so it is for every drift check against a config sheet, where the blank *is* the drift being detected. Writes go the other way regardless: the framework unticks by writing an explicit `false` rather than clearing the cell (`ColumnMetaNamed.actionRowToDefault`, `CheckboxColumnOperator.uncheckActiveCells`).

## `SerialDate`: an in-app date

**An in-app date is a `SerialDate` — a whole-day Sheets serial — never a JS `Date`.** A `date` column's `value` is a count of whole days from the Sheets epoch, branded at the type level so a rent or a count can't be passed where a date is wanted (#15). `SerialDate` is the calendar-day module and its interface is serials in, serials out: build one with `SerialDate.fromYmd`, or with `SpreadsheetNamed.today()`, which dates today in the spreadsheet's own `properties.timeZone`, move by `SerialDate.addDays`/`addMonths` rather than `+ 1` (which widens back to `number` and drops the brand), and don't convert to `Date` at the read line — `serialToDate`/`dateToSerial` are gone, and the whole-day rule lives in one place, `SerialDate.isSerial` — `SerialDate.validate` is its throwing form, and `Val.is.date`/`Val.validate.date` check through that same guard rather than restating it. `SerialDate` holds no clock and no timezone: `SerialDate.fromInstant(instant, timeZone)` is the pure step under `today()`, and a comparison always names the date it compares against. `Tim` is the separate datetime module, still speaking `Date`, taking the timezone as a required argument and epoch and day length from `SerialDate`. The blank is untouched: a blank date cell still reads `""` through `valueOrEmpty` and still throws through the strict words, and a new date cell defaults to that blank (#135).

## `emptyValueAllowed` on the read path

**`emptyValueAllowed` reaches the read path, and shapes the accessor rather than the value type.** It used to be deliberately unwired, on the grounds that the trait asks whether the *column* may hold a blank while the accessor asks whether this *call site* handles one. That held while the trait changed nothing about a read; it stopped holding once the goal was for `value` to be the right call on most columns, so the column's declaration now decides (#13). The trait cannot narrow `ColumnValue` and does not try: clearing a row writes a blank into every non-formula column, unticked ones included, so a blank genuinely can sit there. Note the asymmetry with `checkbox` above — that one is a fact about a type, this one is a promise a throw enforces for the duration of one call. Enforcement stays at access and never at fetch: a sweep over fetched cells would fire on the blank row, on every freshly appended row and on any column whose value name defaults to a blank, and would kill a run over a column nothing read. The write path is unchanged, since tightening writes against the trait would make the blank row unconstructible.
