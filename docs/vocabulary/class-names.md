# Class-name words: tier word, State, Base, Operator, Collaborator

The elaboration behind [docs/vocabulary.md](../vocabulary.md), whose one-line entries are the rules. These are the **architecture** words; the operator-facing ones live in [CONTEXT.md](../../CONTEXT.md).

If you're renaming or relocating something and aren't sure which word fits, ask rather than guess: these distinctions were deliberately hashed out, and folder placement depends on them.

- **Tier word** — every tier class name ends in its tier word: state types (`StateRaw`, `SheetStateIdentified`), bases (`SpreadsheetBaseRaw`, `SheetBaseNamed`) and Common classes (`SheetCommonIdentified`) alike. Each of the Raw, Identified and Named tiers keeps its bases and Common classes in `ClassBases/`. A tier root is named `<Scope>Base<Tier>` (`SpreadsheetBaseSchema`, `SpreadsheetBaseRaw`, `SpreadsheetBaseOperator`), and the rule has no exceptions: the schema classes end in `Schema`.
- **State** — members are named by scope (`sheetState`, `rowState`), and end in the tier word too where one instance holds more than one tier's state at that scope, so they read as their type (`StateRaw` → `spreadsheetStateRaw`, `StateIdentified` → `spreadsheetStateIdentified`). `RawSource` is a port in the Source tier, not a Raw-tier type.
- **Base** — a class root (`<Scope>Base<Tier>`, `ValueSchemaBase`) or an index origin (`Base0`/`Base1`), and nothing else. What the framework supplies whatever the spreadsheet adds is **Framework** (`frameworkValueNames`, `frameworkEndpoints`).
- **Operator** — a class based on a Named base class that adds methods suited to one particular data structure, reaching its subject through a getter rather than inheriting it (see `docs/style/class-shape.md`). An Operator serving this project's own endpoints rather than the framework lives in `src/businessEndpoints/BusinessOperators/`, where `OccupancyLedgerOperator` and `PropertyExpenseOperator` are the two. Config maintenance is one family of Operators, not the definition: `SpreadsheetConfigOperator`/`SheetConfigOperator`/`ColumnConfigOperator`/`ValueConfigOperator` each read a real Config sheet by name and regenerate the matching tier-01 config file, `ConfigCoordinator` coordinates several into one flow after running the config-sheet floor, and `ConfigSheetFloor` restores floor tab titles, Table names, headers, column IDs, group headings and column types, and declares one whole-sheet edit warning on Spreadsheet Config, Sheet Config and Column Config. Maintaining generated data is an Operator-tier job, not Named's. `CheckboxColumnOperator` is the non-config kind, a column operator attachable only to a non-formula `checkbox` column. Resolving a name to a row id, and filling a blank id on the row it resolved, is `SheetNamed.rowIdByName`, not an Operator (#133).
- **Collaborator** — a class a coordinator builds from its own props and reaches through a lazy getter, holding one group of the coordinator's former private helpers. It extends the tier's Base class, is named `<Subject><Role><Tier>` (`SpreadsheetFetcherRaw`, `SpreadsheetFlusherRaw`, `SpreadsheetTableValidatorRaw`), and lives in a subfolder named after its coordinator (`02_SpreadsheetRaw/SpreadsheetRaw/`). Callers use the coordinator, never the collaborator. See `docs/style/class-shape.md`.
