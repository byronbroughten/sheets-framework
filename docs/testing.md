# Testing

Read the heading the task needs.

Vitest, as plain Node against fakes, so `npm test` is always safe. The test-writing rules are the house style's Tests section; this file is the fakes, the seams and the exemplar columns. Most tests need only `stubSheetsService()`.

## Running the tests

Tests run on [Vitest](https://vitest.dev): `npm test` (single run), `npm run test:watch`, or `npm run test:coverage`, from the framework's own `vitest.config.ts`. None of it touches the live spreadsheet or Apps Script — it's plain Node against fakes — so it's always safe to run freely, same as `npm run tsc`.

## Co-located tests

A test is co-located with what it tests — `Foo.ts` → `Foo.test.ts` in the same folder. What it may import: the house style's Tests section.

## Faking spreadsheet I/O with `stubSheetsService`

## `fakeSheetsService.ts`: the fixture-backed Sheets service

`stubSheetsService()` installs that adapter, bound to a fixed spreadsheet ID, so no test stubs a bound spreadsheet to supply one. Fixture `get` / `getByDataFilter` are backed by a real in-memory grid and typed against the actual `GoogleAppsScript.Sheets.Schema` types, so a fixture that drifts from the real response shape is a compile error.

## Which requests the fake replays

**Every request kind the adapter sends is replayed onto the fake's in-memory spreadsheet, in order within a batch and across batches, and a later `get` or `getByDataFilter` in the same test serves the result.** That covers the adapter's whole grammar (`ModeledRequestVerb` in `GoogleSheetsAPI.ts`) plus `updateDimensionProperties`, which only a raw request reaches. A kind with no replay, or a field mask the replay doesn't model, throws naming it, so a new write path can't pass by changing nothing: extend the replay in `src/testSupport/fakeSheetsService/` (one bundle per subject) rather than asserting the request. A batch applies all or nothing, as live. The fake copies its fixture, so one test's writes never reach another test sharing the same fixture object.

**Read what a write left through `stubSheetsService()`'s `grid`**: `grid.sheet(gid)` gives that sheet as it stands when called, with `values(range?)` and `rows(range?)` (a rectangle in the fixture's own cell shape, `null` where empty, defaulting to row 0 and column 0 through the last cell holding anything), `bodyRows(range?)` and `bodyValues(range?)` (the sheet's one Table's body, counted from its first body row and first column, defaulting to the Table's end or the last cell holding anything, whichever is further, so a stray write below or beside the Table still shows), `cell(row, col)`, `rowCount`/`columnCount`, `hiddenRowIndexes`/`hiddenColumnIndexes`, `tables` (Google's shape, as `get` returns them), `protectedRanges` and `conditionalFormats` in order; `grid.sheetByTitle(title)` gives the same view by tab title, and `grid.sheetTitles()` lists the tabs. `batchUpdateCount()` is for a test whose name states a round-trip cost. `isDryRun: true` counts batch updates without replaying them, as the Node host's dry run sends none. `beforeEachBatchUpdate` runs before each batch, so a throw from it stands in for the host refusing a held flush. `afterEachBatchUpdate` edits the fake spreadsheet after each replayed batch, standing in for Sheets keeping a value other than the one sent. Which tests may assert requests instead: [`docs/code-style/tests.md`](./code-style/tests.md#grid-state-over-requests).

What the replay does where the choice isn't obvious, matched to what Google did live ([Tables and growth](./sheets-behaviour.md#tables-and-growth)):

- **Appends**: `appendCells` with a `tableId` inserts its rows at the Table's end, pushing every row below down and growing the grid; without one it writes after the last row holding a value ([observed](./sheets-behaviour.md#appending-rows-to-a-table)).
- **Inserts and deletes**: rows and columns shift, and so do Tables, column types, protected ranges ([observed](./sheets-behaviour.md#row-and-column-shifts)), conditional-format ranges and hidden indexes. An insert strictly inside a Table grows it; one at its end grows it only with `inheritFromBefore: true`, which heads a new column `Column <n>`. That inheriting column insert copies its left neighbour's cell format and cell validation into every row, above the Table too, and a copied checkbox arrives unticked (`false`); it copies no Table column type or column validation rule ([observed](./sheets-behaviour.md#inserting-and-deleting-cells-beside-and-inside-a-table)). The fake copies validation, number format and background colour. A delete inside a Table shrinks it. A Table-bounded column insert or delete leaves rules as measured live, formulas included: a rule over the whole Table grows with an insert and keeps its range under a delete, a rule right of the change moves with its relative references, a whole-Table rule at an insert's column moves with the Table, its `$`-anchored references as written and a relative one at or past the change throwing, by inference from a move measured only as a whole batch (the `cutPaste` bullet below), and an `$`-anchored reference or one to a deleted column stays as written, the delete step's by inference under a rule spanning a move, which was measured only as a whole batch; a one-range rule left of the change, beside the band or out of its rows, keeps its range, and each reference it makes into the band follows its column, whatever its anchors, unless the column was deleted ([insert](./sheets-behaviour.md#column-inserts-bounded-to-a-table), [delete](./sheets-behaviour.md#inserting-and-deleting-cells-beside-and-inside-a-table)); a reference wholly above or below the band's rows stays as written by inference, unmeasured, since a band change moves only the cells in its rows; any other rule shape it reaches throws as unmodelled.
- **`updateTable`**: a field mask replaces only its fields (`name`, `range`, `columnProperties`). A `columnProperties` list replaces the Table's whole list: a column left out keeps its header cell but loses its type and validation, a sent `columnName` is written to the header cell, and a sent column with no name is rejected ([observed](./sheets-behaviour.md#creating-and-updating-tables)). The fake keeps a validation rule's condition type and values, all the adapter reads back, and throws on any other rule field.
- **`deleteTable`**: the Table goes and every cell of its range is blanked, header included, while the cells above its header and the tab stay, and a conditional-format rule wholly over the Table goes with it ([observed](./sheets-behaviour.md#creating-and-updating-tables)); an outside formula's `name[header]` becomes the A1 range of the column's old body rows, though the fake evaluates nothing, quotes a sheet title that isn't a plain identifier in a form no live probe covered, and throws on any other reference form (`name[[#ALL]]`, a column range). The fake keeps a rule reaching past the Table, a case no live probe has covered.
- **`sortRange`**: ascending is numbers, then text, then booleans (`FALSE` before `TRUE`); descending is the exact reverse; blanks sort last in either order ([observed](./sheets-behaviour.md#sorting)).
- **`deleteProtectedRange`** with an id no sheet holds is rejected (`No protected range with id`; [observed](./sheets-behaviour.md#deleting-protections)), and the fake throws likewise.

The Table-bounded requests follow the live probes, and each was rerun live against the fake (sheets-framework#68):

- **`appendDimension`** adds rows or columns past the grid's edge and moves nothing ([observed](./sheets-behaviour.md#the-grids-edge)), but every Table ending on the grid's last row, a side-by-side neighbour included, grows by the rows it adds, its formulas filled ([observed](./sheets-behaviour.md#appending-rows-to-a-table)).
- **`insertRange` and `deleteRange`** shift only the cells inside the range's band, so a Table beside it is spared. A Table the band holds whole moves with it. It grows only by an insert strictly inside it, never by one just below its last row or just past its last column. A delete can leave a Table header only, and a delete of its header row is refused ([observed](./sheets-behaviour.md#inserting-and-deleting-cells-beside-and-inside-a-table)). An insert grows the grid only as far as the cells it pushes past the edge, and a delete leaves the grid's size alone ([observed](./sheets-behaviour.md#the-grids-edge)). The fake leaves the new cells of an insert strictly inside a Table blank, where live they took the format and validation of the cells below ([observed](./sheets-behaviour.md#inserting-and-deleting-cells-beside-and-inside-a-table)).
- **A column insert at a Table's end, an `insertRange` with no `inheritFromBefore`, leaves its new cells blank, as the fake does**, and the recipe-built Layout tab reads 5 columns, as the fake's `layoutSheet` does from its widest Table, and 6 after the insert, which starts inside the grid and so sends no `COLUMNS` `appendDimension` ([observed](./sheets-behaviour.md#column-inserts-bounded-to-a-table)).
- **An insert or delete that would cover part of a Table** throws Google's own `Invalid requests[<i>].<kind>: You cannot insert or delete cells over part of a table.` ([observed](./sheets-behaviour.md#inserting-and-deleting-cells-beside-and-inside-a-table)). The fake throws it when a Table reaches into the band's shifted span but only part of it lies across the band, such as a wider Table below a growing one or a taller one beside a column insert, the two cases seen live ([growth](./sheets-behaviour.md#growing-a-table-with-an-insert-and-a-widen), [column insert](./sheets-behaviour.md#column-inserts-bounded-to-a-table)). A conditional-format rule or protected range cut the same way throws as unmodelled. A whole-sheet protected range has no coordinates to cut, so it stays as it is.
- **A range that starts past the grid's edge** is refused with Google's `Range ('<tab>'!A8:C9) exceeds grid limits. Max rows: 7, max columns: 10`, and one that runs past it is clipped to the grid, for `insertRange`, `deleteRange` and `copyPaste` alike ([observed](./sheets-behaviour.md#the-grids-edge)). That is why growth and a column insert send `appendDimension` first.
- **`copyPaste`** tiles its source over its destination. `PASTE_FORMAT` carries background and number format, and extends a conditional-format rule whose range ends just above the destination; `PASTE_DATA_VALIDATION` carries cell validation; neither touches a value ([observed](./sheets-behaviour.md#copying-format-and-validation-onto-new-rows)). Any other paste type throws.
- **`cutPaste`** (`PASTE_NORMAL` only) moves each cell whole, value, format and validation, and leaves the source empty; when the source holds a Table's whole rows it carries the columns' names, types and validation too, at the grid's edge as away from it ([observed](./sheets-behaviour.md#moving-columns-within-a-table), [at the edge](./sheets-behaviour.md#the-grids-edge)). A conditional-format rule outside the cut source, one over only the destination included, keeps its range and formula when its formula names neither the cut nor the pasted columns, and throws when it names one, a shape no scratch has measured. A sideways cut inside a conditional-format rule over a whole Table's columns leaves the rule as written when its formula names neither the cut nor the pasted columns, as a band move inside a Table did under a whole-row rule with an anchored reference to another column. On a one-column cut to the right it also replays a formula naming them, as that band move did: a reference to the cut column stays as written, and an `$`-anchored one to the pasted column moves one column right, the shift the move's insert gave it and the fake's insert doesn't ([observed](./sheets-behaviour.md#moving-columns-within-a-table)). That the cut step carries the shift is inferred: the move was measured only as a whole insert, cut and delete batch, the only shape in which the framework sends a cut. It replays one move out of a Table, Scratch353D's batch moving a Table's last column to its first position under a whole-Table rule naming the cut column, to the end state measured: the rule's range and formula as written, the Table on the columns right of the paste, and a new one-column Table, `Table<n>` with n one past the spreadsheet's Table count and its ID `fake-table-<gid>-cut-<i>`, over the pasted column, throwing when that name is taken ([observed](./sheets-behaviour.md#moving-columns-within-a-table)). Which step carries each part is inferred, since only the whole batch was measured: the insert at the Table's first column moves the rule with the Table, its `$`-anchored references as written, and the cut moves it one column left over the paste and makes the new Table. The cut reads the formula as the fake's insert left it, so it replays any whole-Table rule whose formula then names neither the cut nor the pasted column, not only one that named the cut column before the insert, by inference: each request replays on its own and can't see what the batch's insert changed. Any other cut of a Table's columns out of it, any other paste type, a cut across sheets, a destination overlapping the source, a relative reference to the pasted column and a source under any other conditional-format rule throw.

The fake stays simpler than Google on purpose: it evaluates no formula (a pasted or written formula reads back as its text, a fixture's formula cell as its computed value), grows the grid for a write past its edge where live refuses, and doesn't set the frozen row `addTable` sets live.

## `getByDataFilter` filters Tables and nothing else

`get` records its params in `getCalls`, so a test can count property fetches. `getByDataFilter` records the resource for assertions and returns only the Tables whose range overlaps one of its filters, as Sheets did when [probed](./sheets-behaviour.md#which-tables-a-grid-fetch-returns), so a Table below the header zone comes back missing and a neighbour no fetch reached stays unknown; `get` returns every Table, and each fixture sheet's `conditionalFormats`, which is how the regen reads rules in a test. A test whose subject needs a Table the filters don't reach, such as the outside-the-zone message, sets `isEveryTableInFilteredFetch` on the stub. Cell data still comes back for every fixture sheet in full, as `get` returns it, but `getByDataFilter` leaves out conditional formats and protections, so a test can assert *what was requested* but never *which cells a filter would have returned*.

## `fakeSheetsHttpTransport`: the Node host's wire over the same fake

`fakeSheetsHttpTransport(fake)` turns a `stubSheetsService()` fake into the Node host's `SheetsHttpTransport`, so a test hands it to `ChoreRunner` or a node host and reads the run's writes through `fake.grid`. It answers the spreadsheet `get`, `:getByDataFilter` (grid-range filters with `includeGridData` only), `:batchUpdate` and `values:batchGet`, for any spreadsheet ID; any other request, query parameter or body key throws, naming its method and URL.

- **`get` and `:getByDataFilter` serve the stub's own payload**, so [its filtering limits](#getbydatafilter-filters-tables-and-nothing-else) hold here too.
- **`:batchUpdate` goes through [the stub's replays](#which-requests-the-fake-replays)**.
- **`values:batchGet` takes `valueRenderOption` `UNFORMATTED_VALUE` or `FORMULA`**, since the fake formats nothing and so can't answer Google's default. It treats any cell showing `""`, a formula's included, as empty, which no live probe has covered. It takes an A1 range with a tab title and a column, whole columns included, quoted unless the title is a plain identifier, and throws on a range past the grid, since live clipping there is unmeasured.

## Fixture Tables, head rows and absent rows

`fakeTableSheet.build` makes a one-Table fixture from a GID, a title, a sheet's column configs, the column names in sheet order and named body rows, putting the column ID and header rows where the layout does; `startRowIndex`/`startColumnIndex` place the Table lower or to the side. Its `tableId`, `name`, `headRows` and column facts (`columnTypes`, `columnValidationValues`, `columnValidationConditionTypes`) pass through to the Table as given, so the column facts stay keyed by absolute column index. A test that only needs a plain Table uses it rather than hand-placing rows. A fixture sheet lists its Tables in `tables`, or gives a one-Table sheet's Table as `table`, never both. Each Table starts where `tableLayout` puts it, so a fixture never asserts a layout production would refuse; `startRowIndex`/`startColumnIndex` override that for a deliberately misplaced Table or a second one lower down or to the side, and `endColumnIndex` narrows the Table inside a wider grid, which is what the real payload looks like whenever a sheet has columns past its Table. A Table's `headRows` gives its head-row cells keyed by offset up from its header (3 is the column ID row), written from its first column, so a stacked Table carries its own head rows; a cell that `rows` gives too throws. An unnamed Table is `fake-table-<gid>`, or `fake-table-<gid>-<i>` at index i. The two absent-row hooks model the two shapes a row with nothing in it really comes back as: `rowsWithNoGridData` emits a block describing every column and carrying no `rowData`, which is what a blank row inside the grid produces, and `rowsWithNoGridBlock` emits no block at all, which is what a row past the populated grid produces (#17).

## `fakeAppsScriptGlobals.ts` and `valueTypesTableSheet.ts`

`fakeAppsScriptGlobals.ts` — `stubScriptAndSpreadsheetApp()` (a fluent trigger builder covering `AppsScript.trigger`'s usage, and an active spreadsheet whose `getId` feeds `GoogleSheetsAPI.forAppsScript()`; `{ spreadsheetId: null }` stands in for a standalone script).

`valueTypesTableSheet.ts` — the dev `valueTypes` Table built with `fakeTableSheet.build`, for behaviour that reads or writes a whole row rather than one named cell (clearing, the blank test, the wipe, append reuse). Anything working from a sheet's *configured* columns resolves each of them against the live columnId row, so such a test needs a fixture listing every column the config declares, which this one does by default from `installedConfigs()`; `valueTypes` has a text and a checkbox column to write and read back. It names a dev Table, so only the framework's tests use it.
## Three seams

SpreadsheetRaw / EndpointRun tests inject a RawSource (`stubSheetsService`). `GoogleSheetsAPI.test.ts` asserts mapping: local operations in, Google requests out; Google payload in, Raw-facing snapshot out. The Node host's HTTP transport is tested at the wire in that same file and in `NodeHost.test.ts`: with a dry run armed, a real framework write through `SpreadsheetRaw` puts nothing on the wire while a read still reaches it. That is the whole safety property in one assertion, and it is the most valuable test around the Node host. The preview renderer is a pure function — Google requests in, lines out — and is tested directly with no seam. The raw request opening is tested at the existing seam, since the fixture already records mapped batch updates and can show a raw request landing last. Chores are not tested (see [Chores](./architecture/chores.md)), and the chore runner's name lookup stays thin enough not to warrant a test — revisit that judgement if it grows past resolving a name to a module. The runner's entered-data gate is tested in `scripts/chore.test.ts`, at the Node host with only its Sheets transport stood in for: a held `--send`, its dry run, then `--send --confirm`. `scripts/chore.fakeTransport.test.ts` asserts the grid a sent chore leaves, over [`fakeSheetsHttpTransport`](#fakesheetshttptransport-the-node-hosts-wire-over-the-same-fake).

## The Apps Script surface and its fakes

Schema/config resolution and ID encode/decode need no mocking. The GAS-touching surface is narrow: `00_Source/GoogleSheets/AppsScript.ts`, `GoogleSheetsAPI.forAppsScript()`, and `appsScriptHost/AppsScriptApi.ts`, which decodes the trigger event with `AppsScript.sheetEdit` and is tested against faked events and globals. Production Raw does not read `Sheets` from global scope. A change that first reaches a new Apps Script global adds its wrapper under `00_Source/GoogleSheets/` and extends `fakeAppsScriptGlobals.ts` in the same change (the rule: [`src/00_Source/GoogleSheets/AGENTS.md`](../src/00_Source/GoogleSheets/AGENTS.md)).

## Three test programs, three config sets

The framework tests (tiers `00`–`06`, `appsScriptHost/`, `nodeHost/` and `testSupport/`) run on the dev spreadsheet's configs, and the app's tests, today `businessEndpoints/`, run on the app's. Each package is its own Vitest project and `tsc` program, so each program carries one `Register` augmentation, in the `appConfigs.ts` that `sync` writes into its `generatedDir`, installed for its tests by `dev/installDevConfigs.ts` and `src/installAppConfigs.ts`. The app's program reaches framework source only through imports, so framework tests never enter it, and `testSupport/` compiles in both. An app test takes its fakes and `EndpointRun` only from `@byronbroughten/sheets-framework/testing`. A framework test reads a GID or column ID through `getTableTraitByName`/`getColumnTraitByName`, and a Table's full column list through `installedConfigs()`, never by importing a `generated/` file. A Table a regen may drop takes a literal GID instead. It never names a real-estate sheet or column, and a made-up sheet in a fixture takes a neutral name such as `Widget`.

The third program, `valueKinds/`, exists because the dev value configs are empty and a program has one `Register`. Its `appConfigs.ts` is hand-written: the dev Tables and columns plus a `widget` Table whose dropdowns use one fixed list (with a number member) and one live reference. It is its own `tsc` program and Vitest project, installed by `valueKinds/installValueKindsConfigs.ts`, and holds the Named-tier and type-level tests of the two value-config kinds ([value configs](./generated-data/value-configs.md#the-two-kinds)).

## The dev fixtures and their exemplar columns

A framework test names a sheet or column of the dev spreadsheet's fixtures, never a real-estate one. `buildDevFixtures` is their checked-in recipe, and the framework's `dev/generated/` is what `sync` read back from them:

| Sheet | Shape | Exemplars |
| --- | --- | --- |
| `item` | ID and Name columns | The main subject of the Raw and Identified tests. `optionalNote` has `emptyValueAllowed` true, and `requiredCount` has it false. |
| `valueTypes` | ID column, one column per framework value name | `sampledBoolean` only *samples* as boolean, with no column type declared. `checkbox` is a declared checkbox. `dateValue` is a declared date. |
| `log` | No ID column | |
| `runItem` | Endpoint sheet: `selected` checkbox, `result` entry column, `startTime` and `runStatus` | The subject of the `EndpointRun`, `Api`, `Endpoints` and `AppsScriptApi` tests, and of the tier 04 tests that need a checkbox column or a conditional-format or protection fixture. |
| `computed` | No ID column | `rowNumber` is the one formula column. |
| `layoutLeft`, `layoutRight` | One `Layout` sheet: Right beside Left within the header zone; Entry and Amount columns each | The subject of the several-Tables tests, built by `layoutSheet` in `spreadsheetRawTestSupport.ts`, and of the `exerciseLayout` dev chore's live run. `layoutSheet` adds an unmanaged `layoutBelow` under Left, so the push tests keep a stacked Table until the zone deepens. |
| `dates` | ID column, two date columns | `requiredDate` has `emptyValueAllowed` false and `optionalDate` has it true, the only such column that is not text, so a blank-allowing read's `SerialDate \| ""` type has a subject. |

Add a fixture sheet only when a test needs a config shape these don't cover. A layout edge case, such as a blank row or a misplaced Table, stays row data in a fake-service fixture. A placement case is tested at the `SpreadsheetIdentified` seam, since the check runs in Identified after the fetch with no finalize hold; Raw's fetch tests see a misplaced Table fetched unjudged. The dev value configs are empty, so no framework test outside `valueKinds/` names a dropdown value name.

An exemplar's value name has to stay put. `sampledBoolean` must not be formatted as a checkbox in Sheets: that would regenerate it as `checkbox` and break `SpreadsheetSchema.test.ts`. The same holds for `emptyValueAllowed`: set `optionalNote`'s to false and a test of the blank-allowing case quietly proves the other one instead of failing. To change a fixture, edit the recipe, delete the tab and rebuild it ([The dev project](./how-it-runs/dev-project.md)).

## Testing an endpoint through `EndpointRun`

The rule and its why: the house style's Tests section and [its reasoning](./code-style/tests.md#endpoints-through-endpointrun). The seam is the run's entry point, driven by the fake Sheets service, and the assertion is the grid the run leaves: which cells hold what values. The real-estate app's `businessEndpoints/buildLedger.test.ts` stubs six sheets at once. The framework half of an endpoint's behaviour is tested separately in `06_API/EndpointRun.test.ts`, against synthetic endpoints on the `runItem` fixture.

## The fake answers what the adapter asked; Google doesn't

Live JSON omits empty lists and zero-valued fields ([observed](./sheets-behaviour.md#empty-lists-and-zero-valued-fields)), echoes each colour as a `*ColorStyle`, and `getByDataFilter` drops sheet-level fields such as `conditionalFormats` ([observed](./sheets-behaviour.md#reading-conditional-formats)). A new read isn't done until a chore dry run has read it from the live sheet (the rule: [`src/00_Source/GoogleSheets/AGENTS.md`](../src/00_Source/GoogleSheets/AGENTS.md)).

## Live-sheet verification

There's no standing integration-test tier against a real spreadsheet. When Claude is asked to extend this test infrastructure, it may use the `gworkspace` MCP ad hoc (within the repo's Sheets write rules; what the MCP can see is [`docs/how-it-runs/gworkspace-mcp.md`](./how-it-runs/gworkspace-mcp.md)'s) to sanity-check that a fake's behavior actually matches the real API — that stays a manual verification step, never part of `npm test`/CI.

## Navigation assertions

Each of `02`–`04` has a spreadsheet-level test pinning every navigation edge — `table`, and `sheet` (in Raw, with its `table`), plus Identified's `tableOnSheet`, where the tier has them, the Table's `column`, `headRow` and row accessors, each one's way back to its Table, and Raw's `profile` — with an identity-based type assertion *and* an `instanceof` check, plus an assertion that no Meta view is offered. The type assertion catches a declaration that widened; the instance check catches an accessor declared for one class but wired to another's constructor, which is structurally valid TypeScript and would otherwise surface only against the live spreadsheet.
