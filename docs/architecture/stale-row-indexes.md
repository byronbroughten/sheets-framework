# Stale row indexes after a flush

Map fragment. Sibling headings live in this folder.

A flushed row delete or sort makes row indexes stale, and a new write method asserts they aren't; growth leaves them valid. Conditional-format rules and edit protections each carry a per-sheet stale flag of their own.

## Stale row indexes after a flush

After row deletes are sent, the **row indexes** of every Table on that sheet are **stale** (`rowIndexesAreStale`). After a sort is sent, only the sorted Table's are, since a sort moves no other Table's rows. Growth sets no flag (sheets-framework#120): the grown Table's end grows when the append is queued (`TableCommonRaw.growDataRowCount`), a pushed-down or pushed-right Table's bounds shift at gathering ([stacked Tables](./stacked-tables.md)), and every row index counts from its Table, so a later flush's writes on either land at their rows after growth. Nothing clears the delete flag within the run, and the throw names the Table and says it needs a refetch in a new run. Row indexes are the first stale axis, flagged per Table. A flush that added or deleted a conditional format rule sets the second, a per-sheet flag (`conditionalFormats.isStale`); a second rule-mutating flush against that sheet is refused until a refetch of its rules clears it. A flush that added or deleted an edit protection sets the third, also per sheet (`editProtections.isStale`); reading or mutating that sheet's protections is refused until a refetch.

## A write that embeds a row coordinate asserts first

Every queue-time write whose flushed request will embed a row coordinate — `updateCells` range, `repeatCell` range, `pasteData` `coordinate.rowIndex`, a row delete's `deleteRange`, both conditional-format rule operations, and a protection whose range or unprotected ranges carry row coordinates read off the sheet — throws because the method's **first line** called `this.table.assertRowIndexesNotStale()` (or the same call on the Table itself). A whole-column protection (start row 0, column bounds, no end row), whose start row is a constant, and a whole-sheet protection with no unprotected ranges, are exempt from it. A new write method ships that assert in the same change; a method that only happens to read `endRowIndex` is not gated. An operation gathered at flush time converts its rows through one method, `TableCommonRaw.originAtGathering`, which throws the same way, so growth, a row delete, a fill, a sort, a column insert, a checkbox, a conditional-format add, a protection with Table rows and any later gathered write refuse a stale Table in one place. `endRowIndex` still throws; the rest of the table object (column range, declared types, validation values, validation condition types) stays readable. Integrating sheet properties afterwards replaces the stored Table range and column properties from the payload but does **not** clear row-index stale — `clearRowIndexStale` is the only restore, unused in production, and nothing in fetch or integrate calls it. Reads by row index stay allowed and may lie. Hybrid cache after a partial refetch, a cross-sheet copy, and content-addressed find/replace are how a lying read can still damage integrity; a later restore without clearing local row state is unsafe.
