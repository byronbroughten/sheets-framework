# Column inserts and column types

Map fragment. Sibling headings live in this folder.

A column is inserted at a Table's end or strictly inside it, or deleted, in a band bounded to the Table and its head rows. Changing a column's type with `updateColumnType` has limits of its own.

## Column inserts are bounded to the Table

No queued operation inserts or deletes whole sheet columns. `TableRaw.appendColumn` inserts at a Table's end. It picks the index, the Table end past the inserts already queued, writes the new column's column ID, header and optional group heading, and returns the index; several on one Table land side by side in queue order. At gathering, `TableRaw.gatherInsertTableEndColumnsOperation` expands a Table's inserts into one `insertTableEndColumns`: an `insertRange` (`COLUMNS`) just past the Table's last column, from header −3 (the column ID row) down to the Table's last row, so the head rows move with the Table, then an `updateTable` with `fields: "range"` widening it, since an insert just past a Table leaves its range alone. Cells above and below that band stay put, and so does a Table below ([observed](../sheets-behaviour.md#column-inserts-bounded-to-a-table)). An insert starting past the grid's edge is refused ([observed](../sheets-behaviour.md#the-grids-edge)), so a Table ending at the grid's last column gets an `appendDimension` (`COLUMNS`) first, summed per sheet like growth's rows. Google heads the new column `Column <n>` until the queued header write renames it ([observed](../sheets-behaviour.md#column-inserts-bounded-to-a-table)), and its Table column type starts Automatic. The band's new cells take no format or validation live, and the fake leaves them blank too ([observed](../sheets-behaviour.md#column-inserts-bounded-to-a-table)). The flush grows the in-memory Table's end column by the insert count, matching the live Table. How an insert moves and guards the Tables to its right: [stacked Tables](./stacked-tables.md#a-column-insert-pushes-the-tables-to-its-right).

## Column inserts inside a Table and column deletes

`TableRaw.insertColumn(colIndex, headCells)` inserts a column strictly inside a Table, from its second column to its last, and `TableRaw.deleteColumn(colIndex)` deletes one, keeping at least one; each reads its index in the layout the Table's earlier queued changes leave. At gathering, `TableRaw.gatherColumnChangesOperation` turns them, in queue order, into one `changeTableColumns`: per change, an `insertRange` or `deleteRange` (`COLUMNS`) one column wide, from the column ID row to the Table's last row. An insert strictly inside a Table grows it with no `updateTable` ([observed](../sheets-behaviour.md#column-inserts-bounded-to-a-table)), and a delete shrinks it. Each change takes the same neighbour-split guard as `appendColumn`, naming its own action. The gather moves the working view with each change: the fetched cells and column facts right of it are rekeyed, an inserted column's cells read empty, the column count moves by one, the fetched column list is cleared as `updateColumnType` clears it, and an insert's head cells are queued as cell writes, sent after the change. Every other write queued on the Table is indexed by the columns before the change, so the gather refuses a column change alongside any of them: it goes in a flush of its own on its Table. The Tables to its right shift by the net change, a negative count for more deletes than inserts. A column delete removes a conditional-format rule or protection it holds whole, so the flush marks that sheet's fetched rules and protections stale.

## `updateColumnType` has three limits

One update per fetch: the flush clears the Table's fetched column list, so another update before a refetch throws. It refuses, before anything is sent, when the same flush inserts or deletes a column on that sheet, and on a Table with a validated column, because a restore resets its dropdown style and colours.
