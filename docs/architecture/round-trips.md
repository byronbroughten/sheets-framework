# Round trips are the cost

Map fragment. Sibling headings live in this folder.

Where the Sheets API is called, what a round trip costs, and how reads ride a fetch that is already happening.

## The chokepoints

Every call to the Sheets API funnels through exactly two methods — `SpreadsheetRaw.fetchAllGathered` (reads) and `SpreadsheetRaw.batchUpdateGSheets` (writes), both carried out by collaborators in `02_SpreadsheetRaw/SpreadsheetRaw/` — which call `RawSource.fetchGrid` / `RawSource.flush`. `fetchAllSheetProperties` is the third I/O method (`RawSource.fetchSheetProperties`). Instrument those and you have measured everything. Google's three Advanced Service verbs (`Spreadsheets.get`, `getByDataFilter`, `batchUpdate`) live only in `GoogleSheetsAPI`. Why the cost is deliberately funnelled that way: [`docs/design.md`](../design.md), "Funnel the expensive thing through one place".

Measured against the live spreadsheet (Sept 2026): a round trip costs **~250–450ms**, while the framework's own CPU for a whole trigger is **~20–60ms**. Making the code faster does not move the number; removing a round trip is the only thing that does. The `triggerOnEdit` **dispatch** is down to two — one read for the column indexes and table bounds, one write — which is the floor, since neither can be derived without asking the API. A *runner* costs more, and the extra write is deliberate: the setup flush is what puts the running state on the sheet before the work starts.

## Riding a fetch

`fetchAllPrepped` is two-phase by design — one `fetchAllGathered` for prerequisites, then one for the data ranges prepped against the indexes the first phase resolved — and `fetchAllGathered` no-ops when nothing is gathered. **A read prepped into that second phase is free whenever a prerequisite fetch is already happening**, which is the lever for adding a data read to a trigger without adding a round trip. Gathering a sheet's conditional format rules is the same kind of ride: it is a new gather on the Raw sheet, included in the grid field mask when that gather is set, so it is free when a fetch is already happening and an explicit round trip when it is not. Edit protections ride the same way, as their own gather and a plain get with a `protectedRanges` fields mask — never `getByDataFilter`. Extending the standing sheet-properties fields mask was rejected — in production only the config orchestrator calls that, so no other path would get rules, and every path would pay. The time zone rides all three standing masks; `SpreadsheetRaw.timeZone` gets it alone only before any fetch. The grid's `rowCount` and `columnCount` and each Table column's `columnType` ride the sheet-properties and grid masks too, which is what lets Table growth and a column insert size their `appendDimension` and growth pick its validation copies without a round trip of its own.

## Table ranges and Table-bounded reads

**A table's range reaches state by two routes, with different coverage.** `fetchAllSheetProperties` issues one sheet-properties fetch and returns every sheet's table range unconditionally; in production only `ConfigCoordinator` calls it, at the top of a config sync. Every other path, the `triggerOnEdit` dispatch included, gets table metadata only as a side effect of a grid fetch, which returns a sheet's `tables` for a filter whose range overlaps the table and otherwise omits it silently. That is why `TableRaw.gatherFetchProperties` gathers the placement strip, from row 0 down to the recorded header in the recorded start column: it overlaps the header cell while the Table is where it was recorded, and it carries the column ID row's first cell for the placement check ([table placement](./table-placement.md)). A Table moved out of the strip's sight comes back absent and stops the run as missing, so the blind spot costs no round trip. The column-id row that shares the strip's round trip uses that same recorded start (unbounded on the right), because those columns are where the recorded Table holds its IDs. Do not add a sheet-properties fetch to every gathered fetch to close the strip's blind spot without a new decision.

**Once a Table's properties are in state, every read is Table-bounded, and still one `fetchGrid` round trip** (sheets-framework#62). A full row is the Table's own columns, a full column runs from header −3 (the column ID row) to the Table's last row, and a single cell is itself. Integration routes each fetched cell to the Table whose area (header −3 down, across its columns) holds it, counted from that Table's own first row and column, and drops a loose cell that sits in no Table. Every Table a snapshot carries gets state keyed by its `tableId`, and one a grid fetch leaves out keeps its state, since only a fetch covering a whole sheet lists every Table on it; dropping Tables absent from the configs waits for `tableConfigs`.

## Rejected: `SpreadsheetApp`

**`SpreadsheetApp` is not a cheaper alternative, despite the intuition that a trigger already has the sheet open.** Measured the same day: `getLastRow()` + `getLastColumn()` + `getRange().getValues()` cost ~494ms against ~350ms for the single `getByDataFilter` they would have replaced. Each `SpreadsheetApp` call is its own round trip. This was tested and rejected — don't re-propose it without new measurements.
