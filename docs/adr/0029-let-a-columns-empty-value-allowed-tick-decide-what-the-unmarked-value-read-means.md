# Let a column's Empty value allowed tick decide what the unmarked `value` read means

Nearly every cell read is one where a blank means the endpoint can't do its job, so the unmarked `value` validates: it excludes the blank from its type and throws naming the cell, unless the column's Empty value allowed tick says a blank is legitimate there, where it keeps the blank and returns it. `valueOrEmpty`, which never throws on a blank, and `valueNotEmpty`, which always does, are the marked words, so the name at a call site records what was decided about blanks. Only Named can see the declaration, so Identified, which resolves columns by generated ID, offers only the two marked words and Raw only `valueOrEmpty`, and no word carries two contracts one tier apart. The tick shapes the accessor, not the column value type, since clearing a row writes a blank into any non-formula column, and it is enforced at access, never at fetch, which would fire on the blank row and stop a run over a column nothing read. The first form of this decision kept the tick off the read path as action at a distance; that was reversed once the aim became an unmarked read that is right on most columns, not only on those that can't be blank.
